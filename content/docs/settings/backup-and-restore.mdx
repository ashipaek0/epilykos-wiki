Your settings, layouts, metrics and history all live in one database file. **Settings → Backup and
restore** lets you download it, restore it, and roll back to one of the automatic snapshots.

![Settings → Backup and restore](/images/settings-backup.webp)

## Download a backup

Press **Download backup** to save the whole database as a single file.

The passwords and tokens you've saved (for Solcast, MQTT, Home Assistant, Tuya, notifications and so
on) are inside that file, locked with a key that stays on this box. That means if you restore the file
onto a different box, those passwords can't be unlocked and you'd have to type them in again.

To take them with you, switch on **Protect saved passwords with a passphrase** before downloading, and
choose a passphrase of 8 to 256 characters. The saved passwords in that file are then locked with your
passphrase instead of the box's key.

<Callout type="warn" title="The passphrase can't be recovered">
  It isn't stored anywhere. Keep it with the backup file, somewhere other than the box itself.
</Callout>

A backup copied off the box is your real safety net: the daily snapshots live on the same card or disk
as everything else.

## Restore

Press **Restore from file…** and pick a backup. Everything is replaced with what's in the backup.

If the backup was made with a passphrase, Epilykos asks for it after the upload, then locks the
passwords again with the new box's own key. A wrong passphrase is refused and you're asked again, and
nothing is replaced until you give the right one or cancel. If you've lost the passphrase, **Restore
without saved passwords** restores everything else and leaves the saved passwords empty.

A few things a backup doesn't include:

- **Two-step sign-in**: a restored box starts with it switched off.
- **Tailscale**: you'll need to connect remote access again.

## Automatic snapshots

Every day, Epilykos takes a compressed snapshot of the database and checks that it's sound, and it
keeps the two newest good ones. Press **Restore** next to a snapshot to roll back to it, or **Refresh
snapshots** to update the list.

If a snapshot fails, or there hasn't been a recent one, Epilykos raises the **Automatic snapshot
failed** or **Automatic snapshot overdue** event; you can choose to be told in
[Notifications](/settings/notifications).

## Remote backup

A backup that stays on the same card or disk does not help if the card fails or the box is stolen.
**Remote backup** sends an encrypted copy of your latest snapshot to somewhere else, every week by
default. It's off until you switch it on.

Choose **Where to send it**: a folder, a WebDAV server or Google Drive.

- **Folder or drive on this box:** a USB drive, a network share you have mounted, or a folder you mapped
  into Docker as a volume. Mount the drive first. Epilykos creates only the last folder of the path, so a
  drive that isn't mounted can't fill the card by accident.
- **WebDAV server:** Nextcloud, ownCloud, Synology, a Hetzner Storage Box and other servers that speak
  WebDAV. Fill in the **Server address**, a **Folder** (created inside that address if it's missing, but
  only that last folder), your **Username** and an **App password**. For Nextcloud, use the WebDAV address
  from its Files settings, and make an app password for this box in its security settings instead of using
  your main password.

**Test connection** checks that Epilykos can sign in and write there. For a folder it also warns you if the
folder is on the same disk as Epilykos's own data, which wouldn't survive that disk failing. For a WebDAV
address that starts with `http://` it warns that the password travels unencrypted, so use `https://` unless
the server is on your own network. The backup itself is always locked, either way.

A WebDAV copy is stored as several parts of about 32 MB and a small record, so servers and proxies that limit
the size of a request still accept it. The record is written last, which means a copy that was cut short is
never listed, and the next run clears its leftover parts. A copy is checked by the size of every part as the
server reports it, because WebDAV has no standard checksum. **Check copy** and **Restore** check the whole
file when you use them. Epilykos doesn't follow redirects: if the server redirects, it tells you the
address to use instead.

**A server with its own certificate.** Epilykos always checks certificates. If your server uses one you made
yourself, paste its SHA-256 fingerprint in **Certificate fingerprint**. Only that exact certificate is then
trusted, and a different one is refused. Find the fingerprint in your browser's certificate details, or run
`openssl x509 -in cert.pem -noout -fingerprint -sha256`. Leave it empty for a normal https address.

**Google Drive.** Choose **Google Drive** and press **Connect Google Drive…**. Epilykos shows a short code
and an address. On any phone or computer, open the address, sign in to Google and enter the code; Epilykos
waits and finishes by itself, so nothing needs to reach your box from the internet. Backups go in a folder
called **Epilykos** in your Drive, which you can see and delete yourself.

Epilykos asks Google for one permission only: to see and manage **the files it creates itself**. It can't
see your other files, your email or anything else about your account. The sign-in is stored on the box,
locked with the box's key, and is part of a downloaded backup like your other saved passwords. See
[Privacy](/privacy) for the details.

- A copy is sent in chunks, and Google's own checksum of the file is compared with Epilykos's before an older
  copy is deleted.
- If you use the same Drive for more than one Epilykos box, each box only ever deletes its own copies. Copies
  from the other boxes are still listed, so you can restore them.
- **Disconnect** tells Google that Epilykos no longer needs access, forgets the sign-in on the box and
  switches off a Google Drive backup. Copies already in your Drive stay until you delete them. You can also
  remove access at [myaccount.google.com/permissions](https://myaccount.google.com/permissions).
- If Google ever withdraws the access (you removed it there, or it expired), the next backup fails with
  "Google Drive access was removed or has expired", the earlier copy stays, and you press **Connect Google
  Drive…** again.
- If the card says Google Drive is **not set up in this build**, the copy of Epilykos you run doesn't include
  the Google sign-in details. Use a current release.

| Setting | What it does |
| --- | --- |
| **Passphrase** | Required. It locks the whole copy, history included, before it's written, so whoever holds the drive or the server sees only noise. At least 8 characters. |
| **How often** | Weekly or daily. Scheduled uploads start between 01:00 and 06:00. |
| **Copies to keep** | 1, 2 or 4. A new copy is checked before an older one is deleted, so the destination briefly holds one more than you chose. |

When you save a new passphrase, Epilykos asks you to confirm that you have kept it.

<Callout type="warn" title="The passphrase can't be recovered">
  It's stored on the box, locked with the box's key, along with the WebDAV password, but it isn't stored anywhere else. If you lose
  both the box and the passphrase, the copies can't be opened by anyone. Keep it somewhere other than
  the box. Changing it later doesn't re-lock older copies: they keep the passphrase they were made with
  until newer copies replace them.
</Callout>

Once it's switched on you'll see when the last copy was sent, when the next one is due, and the copies
held at the destination. Each copy has two buttons:

- **Check copy** confirms the passphrase opens the copy and that its start is intact, without restoring anything.
- **Restore…** downloads it, unlocks it and replaces everything on this box with it, like restoring a snapshot. Leave the passphrase empty to use the saved one, or type the one the copy was made with.

**Back up now** takes a fresh snapshot and sends it straight away. If a copy fails, the earlier one stays
where it is, Epilykos tries again after 30 minutes, then less often, and raises **Remote backup failed**
(and **Remote backup overdue** if it goes much longer than your schedule). You can be told in
[Notifications](/settings/notifications).

Each upload is a full copy of your snapshot, because encrypted data can't be sent as changes. Check the
size of your latest snapshot in **Automatic snapshots** and choose weekly if your connection is slow or
metered.

## Database health

**Database health and backups** shows when you last downloaded a backup, and the result of the last
database check. **Check the database now** runs a check straight away. Epilykos also checks
automatically a minute after an unexpected stop (a power cut, say), and once a week.

Once a month, a reminder asks you to download a backup; the daily snapshots don't count, because they
stay on the same card or disk. **Remind me about backups in 7 days** puts it off for a week.
