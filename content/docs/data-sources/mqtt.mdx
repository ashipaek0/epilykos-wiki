The **MQTT** source subscribes to topics on your MQTT broker (Mosquitto, EMQX and the like) and saves
each message it receives as a metric value.

## What you need

- The broker's address, for example `mqtt://192.168.1.50:1883`.
- A username and password, if your broker needs them. They're stored encrypted.

## Set it up

<Steps>
<Step>

In **Settings → Sources**, press **+ Add MQTT broker** and give it a name.

</Step>
<Step>

Enter the broker's address and, if needed, the username and password, then press **Test Broker**.

</Step>
<Step>

Press **🔍 Discover Topics** to see what's being published, or type in the topics yourself. **Test
Topic** waits for the next message on a topic and shows you what arrived.

</Step>
<Step>

Press **+ Add Metric Mapping** for each value, pick a metric name, and enter its topic. Then **Save
changes**.

</Step>
</Steps>

## One value per topic

Each topic you map needs to carry a single value, such as `1234` or `on`, because Epilykos saves the
message exactly as it arrives. A JSON message (like Tasmota's `tele/…/SENSOR`) is saved as one long
piece of text rather than split into fields, so it won't show up on a chart. Have the device publish
each value on its own topic, or read it with the [REST API](/data-sources/rest-api) source instead.

Topics have to match exactly; wildcards (`+` and `#`) don't work in mappings.

## Alerts

When an established connection to the broker drops, and again when it comes back, Epilykos raises the
**MQTT broker disconnected** and **MQTT broker reconnected** events. You can be told about them in
[Notifications](/settings/notifications).

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Connection refused | The broker isn't running, or the port is wrong | Check that the broker is running (`systemctl status mosquitto`). The usual port is 1883. |
| Authentication fails | The username or password is wrong | Check them against your broker's configuration. |
| No data | Nothing is being published on the topic | Watch everything the broker receives with `mosquitto_sub -t "#" -v`. |
