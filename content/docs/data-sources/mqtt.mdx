The **MQTT** source subscribes to topics on any broker (Mosquitto, EMQX and so on) and stores each
message as a metric value.

## What you need

- The broker URL, for example `mqtt://192.168.1.50:1883`.
- A username and password if the broker needs them. They are stored encrypted.

## Set it up

<Steps>
<Step>

In **Settings → Sources**, press **+ Add MQTT broker** and give it a name.

</Step>
<Step>

Enter the broker URL and, if needed, the username and password. Press **Test Broker**.

</Step>
<Step>

Press **🔍 Discover Topics** to see what is being published, or type topics yourself. **Test Topic**
waits for the next message on one topic and shows it.

</Step>
<Step>

Press **+ Add Metric Mapping** for each value: pick a metric name and enter its topic. Then **Save
changes**.

</Step>
</Steps>

## One value per topic

Each mapped topic must carry a single value, such as `1234` or `on`. The message is stored exactly as
it arrives: a JSON message (like Tasmota's `tele/…/SENSOR`) is stored as text, not split into fields,
and won't chart. Publish the values on their own topics, or read the device with the
[REST API](/data-sources/rest-api) source instead.

Topics are matched exactly; wildcards (`+`, `#`) aren't used for mappings.

## Alerts

Epilykos sends the **MQTT broker drops** and **reconnects** events when an established connection
is lost and comes back. Use them in [Notifications](/settings/notifications).

## Troubleshooting

| Symptom | Likely cause | Fix |
| --- | --- | --- |
| Connection refused | Broker not running, or wrong port | Check the broker is running (`systemctl status mosquitto`). The default port is 1883. |
| Auth failure | Wrong username or password | Check the credentials in your broker's configuration. |
| No data | Nothing is published on the topic | Watch the broker with `mosquitto_sub -t "#" -v` to see what's published. |
