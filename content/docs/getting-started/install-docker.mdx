Epilykos is published as a Docker image, `irunmole/epilykos:latest`, for 64-bit x86 and ARM (`amd64`
and `arm64`). It runs wherever Docker does, on a computer that stays on: Windows or macOS with Docker
Desktop, a Linux PC or server, a NAS, or a Raspberry Pi with a 64-bit OS.

## What you need

- Docker with Compose: [Docker Desktop](https://docs.docker.com/desktop/) on Windows and macOS, or
  [Docker Engine](https://docs.docker.com/engine/install/) with the Compose plugin on Linux.
- For Bluetooth batteries or inverter modules: a Linux host with a Bluetooth adapter and BlueZ running.
- For RS232 or RS-485 equipment: a USB serial adapter.

<Callout title="On Docker Desktop (Windows, macOS), hardware takes extra steps">
  Docker Desktop runs containers inside a virtual machine. Sources that work over the network
  (Wi-Fi dongles, Modbus-TCP, Home Assistant, MQTT, REST APIs, and Tuya devices added by hand) work
  as is. USB serial adapters can be passed in with USB/IP, Bluetooth needs a Linux host, and Tuya
  discovery may not work. See [Docker Desktop on Windows and macOS](#docker-desktop-on-windows-and-macos).
</Callout>

## Install

<Steps>
<Step>

### Get the compose file

Make a folder for Epilykos and download the compose file into it:

<Tabs items={["Linux and macOS", "Windows (PowerShell)"]}>
<Tab value="Linux and macOS">

```bash
mkdir epilykos && cd epilykos
curl -fsSLO https://raw.githubusercontent.com/ashipaek0/Epilykos/main/docker-compose.yaml
```

</Tab>
<Tab value="Windows (PowerShell)">

```powershell
mkdir epilykos; cd epilykos
curl.exe -fsSLO https://raw.githubusercontent.com/ashipaek0/Epilykos/main/docker-compose.yaml
```

</Tab>
</Tabs>

Epilykos keeps everything it stores in the `data` folder next to this file.

</Step>
<Step>

### Choose how the admin password is set (optional)

By default, the first person to open the setup wizard chooses the admin password. If people you
don't trust can reach this computer before you've done that, set the password in the compose file
instead: turn on the `environment:` block and add a line for it.

```yaml title="docker-compose.yaml"
    environment:
      - SETTINGS_PASSWORD=choose-a-long-password
```

<Callout type="warn" title="A .env file is not enough">
  The compose file doesn't load a `.env` file into the container, so `SETTINGS_PASSWORD` written in
  `.env` has no effect. Put it under `environment:` as above.
</Callout>

Use at least 12 characters (remote access refuses a shorter admin password), and write each `$` in it
as `$$`, because Compose reads `$` as the start of a variable. A password set this way can't be
changed from Settings; change it in the compose file and run `docker compose up -d` again.

</Step>
<Step>

### Start Epilykos

```bash
docker compose up -d
```

</Step>
<Step>

### Run the setup wizard

Open `http://localhost:3000/setup` in a browser on the same computer, or
`http://<this-computer>:3000/setup` from another device, for example `http://192.168.1.10:3000/setup`.
The [setup wizard](/getting-started/first-run-setup) walks you through the password, your equipment
and a first dashboard.

</Step>
</Steps>

## The compose file

```yaml title="docker-compose.yaml"
services:
  epilykos:
    image: irunmole/epilykos:latest
    container_name: epilykos
    restart: unless-stopped
    ports:
      - "3000:3000"                  # Ignored with network_mode: host (the app then listens on host port 3000)
    volumes:
      - ./data:/app/data
      - /etc/localtime:/etc/localtime:ro   # The container follows this computer's time zone.
      - /run/dbus:/run/dbus:ro       # Bluetooth BMS / inverter Bluetooth modules: talk to the host's BlueZ over D-Bus.
      # "Update now" in Settings → Updates. This gives Epilykos full control of Docker on
      # this computer (it could start any container), so only keep it if you want one-click
      # updates. Without it, update with: docker compose pull && docker compose up -d
      - /var/run/docker.sock:/var/run/docker.sock
    security_opt:
      - "apparmor=unconfined"        # Lets the container reach the host's Bluetooth service on Ubuntu; harmless elsewhere.

    # ── Option: USB serial adapter (RS232 / RS485 inverter or wired BMS) and/or the Bluetooth group.
    # devices:
    #   - "/dev/ttyUSB0:/dev/ttyUSB0"
    # group_add:
    #   - "dialout"                  # Serial port permission.
    #   - "108"                      # The host's bluetooth group ID, from `getent group bluetooth`.

    # ── Option: a time zone other than this computer's (uncomment both lines).
    # environment:
    #   - TZ=Europe/London

    # ── Option: host networking, only for Tuya LAN broadcast discovery (then `ports` above is ignored).
    # network_mode: "host"
```

Options that are off start with `# `. To turn one on, remove the `# ` from **every** line of its
block, the key and its items together, and keep the indentation as it is. A key with nothing under it
(for example `devices:` on its own) is an error. `docker compose config` prints the file or tells you
what is wrong. Then run `docker compose up -d`.

### USB serial adapters

On Docker Desktop, first hand the adapter to Docker: see
[USB adapters on Docker Desktop](#usb-adapters-on-docker-desktop). For an RS232 or RS-485 inverter, or a
wired BMS, turn on `devices:` with one line per adapter, and `group_add:` with `dialout` for permission to use them. Docker refuses to start the container if a
listed device doesn't exist, which is why this is off until you need it.

```yaml
    devices:
      - "/dev/ttyUSB0:/dev/ttyUSB0"
    group_add:
      - "dialout"
```

Adapters can change names when they're unplugged. `ls /dev/serial/by-id/` lists stable names you can
use on the left side instead.

### Bluetooth

Needs a Linux host (not Docker Desktop). Bluetooth batteries and inverter modules are built in. They use the host's
Bluetooth adapter through BlueZ over D-Bus, which the `/run/dbus` line (on by default) provides.

- The host must run BlueZ with a powered adapter: `systemctl status bluetooth` shows *active*, and
  `bluetoothctl show` shows `Powered: yes`.
- If Settings reports *D-Bus denied access to BlueZ*, turn on `group_add:` and add the host's
  `bluetooth` group ID, from `getent group bluetooth`.
- `security_opt: apparmor=unconfined`, already in the file, covers Ubuntu hosts.

### Time zone

Daily totals roll over at midnight in the container's time zone. By default it follows the host
(the `/etc/localtime` line). To use another, turn on `environment:` with a `TZ=` line. The startup log
line shows the active time zone.

On Docker Desktop, set `TZ`; see [Time zone on Docker Desktop](#time-zone-on-docker-desktop).

### One-click updates

The `docker.sock` line lets **Settings → Updates → Update now** download the new image and restart
Epilykos on it. It also gives Epilykos full control of Docker on this computer, so remove the line if
you don't want that and update with the commands below.

### Tuya discovery

Tuya devices announce themselves with LAN broadcasts, which only reach the container with host
networking on a Linux host (on Docker Desktop, see [Tuya discovery on Docker Desktop](#tuya-discovery-on-docker-desktop)). Turn on `network_mode: "host"` only if you use Tuya discovery; the dashboard is then on
host port 3000 and `ports:` is ignored.

## Docker Desktop on Windows and macOS

Docker Desktop runs containers inside a virtual machine, so the computer's own hardware doesn't reach
Epilykos directly. Sources that work over the network (Wi-Fi dongles, Modbus-TCP, Home Assistant,
MQTT, REST APIs, Tuya devices with known addresses) need nothing extra.

### USB adapters on Docker Desktop

Possible with USB/IP, which hands the adapter to Docker's virtual machine:

- **Windows with the WSL 2 backend** (Docker Desktop's default): install
  [usbipd-win](https://learn.microsoft.com/windows/wsl/connect-usb) and, in an administrator
  PowerShell, run `usbipd list`, then `usbipd bind --busid <id>` once and
  `usbipd attach --wsl --busid <id>`. The adapter then shows up as a Linux device such as
  `/dev/ttyUSB0`; map it under `devices:` as above.
- **macOS, and Windows with the Hyper-V backend**: follow
  [Using USB/IP with Docker Desktop](https://docs.docker.com/desktop/features/usbip/). It runs a USB/IP
  server on the computer and a privileged helper container that attaches the device. The helper has to
  keep running.

The attachment doesn't survive a restart of the computer or of Docker Desktop unless it is redone;
`usbipd attach --wsl --busid <id> --auto-attach` keeps reattaching on Windows while it runs. Common
adapter chips (CH340, CP210x, FTDI) usually work, but neither Docker nor Microsoft guarantees every
device.

For a Modbus inverter on RS-485, an RS-485 to Ethernet gateway avoids USB altogether and works from
any Docker host; see [Modbus](/data-sources/modbus#ways-to-connect).

### Bluetooth on Docker Desktop

Not supported on Docker Desktop. Epilykos talks to the host's Bluetooth service (BlueZ) over D-Bus,
and Docker Desktop's virtual machine has none. Run Docker on Linux, or use
[EpilykosOS](/getting-started/install-epilykos-os), for Bluetooth batteries and inverter modules.

### Tuya discovery on Docker Desktop

Docker Desktop 4.34 and later has opt-in host networking (**Settings → Resources → Network → Enable
host networking**), but it forwards TCP and UDP connections rather than joining your network, so
Tuya's broadcast announcements may still not arrive. If discovery finds nothing, enter each device's IP
address by hand; see [Tuya](/data-sources/tuya#add-a-device-by-hand).

### Time zone on Docker Desktop

Set `TZ` under `environment:`: the `/etc/localtime` line may not carry your computer's time zone into
the container.

## Updating

```bash
docker compose pull && docker compose up -d
```

With the Docker socket mounted you can use **Settings → Updates** instead. See
[Updates and system](/settings/updates-and-system).

The `latest` tag follows releases. `irunmole/epilykos:dev` follows development builds, for testing
what's coming next.

## Environment variables

Add any of these under `environment:` in the compose file.

| Variable | Default | Purpose |
| --- | --- | --- |
| `SETTINGS_PASSWORD` | not set | Admin password, at least 12 characters (write `$` as `$$`). When set, it can't be changed in Settings. |
| `TZ` | host time zone | Time zone for daily totals, e.g. `Africa/Lagos`. |
| `PORT` | `3000` | Port Epilykos listens on inside the container. |
| `LOG_LEVEL` | `info` | Starting log level: `debug`, `info`, `warn` or `error`. A level chosen in Settings → Logs overrides it. |
| `LOG_TO_FILE` | `true` | `false` logs to stdout/stderr only, for read-only container roots. |
| `LOG_DIR` | `logs/` | Where rotating log files go when file logging is on. |
| `SQLITE_SYNCHRONOUS` | `NORMAL` | Database durability: `NORMAL`, `FULL` or `EXTRA` (`OFF` is refused). |
| `TMPDIR` | `/tmp` | Temporary folder for uploads (backup restore, layout import). |
| `BLUETOOTH` | `on` | `off` disables Bluetooth even when `/run/dbus` is mounted. |
| `BLE_KEEP_ALIVE` | `true` | Keep Bluetooth connections open between reads. `false` reconnects every read: slower, but frees adapter slots. |
| `BLE_MAX_LINKS` | `1` | Bluetooth devices kept connected at once. Raise it if your adapter handles several connections well. |
| `BLE_LOG_LEVEL` | `WARNING` | Bluetooth helper log level (`INFO` or `DEBUG` when diagnosing a device). |
| `UPDATE_CHECK` | `on` | `off` never checks for updates. |
| `SESSION_SECRET` | generated | Sign-in session secret. If unset, one is generated and kept in `data/session-secret`. |
| `RESET_TWO_STEP` | not set | `true` turns two-step sign-in off at start. Remove it again afterwards. See [Security](/settings/security). |

## Health check

`GET /healthz` needs no login. It returns `200 {"status":"ok",…}` once Epilykos is serving and its
database opens with the expected schema, and `503` otherwise. It never depends on the internet, so a
box without internet stays healthy. The image uses it as its Docker `HEALTHCHECK`.

## What's in the data folder

| Path | What it is |
| --- | --- |
| `data/energy.db` | The database: settings, layouts and history. |
| `data/snapshots/` | The automatic daily snapshots of the database (the last 2 are kept). |
| `data/settings-password` | The admin password, hashed (not used when `SETTINGS_PASSWORD` is set). |
| `data/encryption-key` | The key that encrypts saved passwords and tokens. |
| `data/two-step.json` | Two-step sign-in, when it is on. |
| `data/session-secret` | Sign-in session secret. |
| `data/tailscale/` | Tailscale state, when remote access is on. |

Backups downloaded from Settings contain the database only. Keep a copy of the whole `data` folder if
you want to move an install with its saved passwords intact; see
[Backup and restore](/settings/backup-and-restore).
